把产品手册、真实界面、操作录屏与品牌素材，组织成一条观众能理解的产品故事。先产出可执行的分镜脚本，确认后推进关键帧、交互动画、声音与完整视频制作。

这份 Skill 提炼自 **DramaTV、DramaFlow、DramaData** 宣传视频的制作与修改经验，尤其关注中文排版、真实操作顺序、鼠标点击、步骤提示和多轮修改的连续性。新产品可以采用自己的品牌视觉。

> **你提供产品资料与目标，先确认脚本，再获得成片与可编辑工程。**
> 本仓库提供制作方法、参考规范、分镜模板和时序检查工具；渲染、配音及生成式素材需要运行环境中的相应工具。

## 能做什么

| 任务 | 制作重点 | 产出 |
| :--- | :--- | :--- |
| 产品宣传片 | 从受众与产品价值出发，串起真实任务链 | 分镜脚本、完整视频、工程 |
| 新功能演示 | 操作前提、点击动作、状态反馈与最终结果 | 连贯的功能演示片段 |
| 界面动效 | 输入、步骤高亮、画布连线、卡片展开与过渡 | 可逐帧调整的界面动画 |
| 既有视频修改 | 找到对应工程，保留已确认内容，定点修改 | 关键帧预览或新版本视频 |
| 资料转脚本 | 整理能力证据、叙事主线与素材缺口 | 可进入制作的分镜表 |

## 制作流程

```mermaid
flowchart LR
    A[产品资料与真实界面] --> B[产品理解与素材核验]
    B --> C[完整分镜脚本]
    C --> D{用户确认脚本}
    D -->|调整| C
    D -->|确认| E[关键帧与界面动效]
    E --> F[动态检查与声音制作]
    F --> G[整片渲染与质量检查]
    G --> H[MP4 + 工程 + 制作记录]
```

| 阶段 | 你会看到什么 |
| :--- | :--- |
| 理解产品 | 受众、核心价值、可展示能力、资料缺口 |
| 确认脚本 | 每镜时长、上屏文案、旁白、交互、素材、转场与声音 |
| 制作画面 | 统一的字体、色彩、输入框、步骤提示和鼠标样式 |
| 检查动效 | 点击前后状态正确，文字稳定，转场自然，信息有阅读时间 |
| 交付成片 | 可播放视频、可编辑工程、复现命令和检查记录 |

说“先看关键帧”，就先看关键帧；脚本确认后说“生成视频”，就进入整片制作。

## 快速开始

### 1. 安装

将本仓库下载后，把文件夹命名为 `product-promo-film`，放入 Codex 的技能目录：

```text
~/.codex/skills/product-promo-film/
└── SKILL.md
```

Windows 默认位置为 `%USERPROFILE%\.codex\skills\product-promo-film`。请同时保留 `agents`、`assets`、`references` 和 `scripts` 文件夹。

也可以把仓库地址交给支持安装技能的助手：

```text
请帮我安装这个 Skill：
https://github.com/lisalisacailisa-dotcom/product-promo-film
```

### 2. 提供资料

| 资料 | 用途 |
| :--- | :--- |
| 产品手册、功能说明 | 明确产品能力与宣传边界 |
| 受众、投放场景、目标时长 | 决定叙事重点与信息密度 |
| Logo、品牌字体、配色 | 建立一致的视觉风格 |
| 界面截图、录屏、演示环境 | 核验真实流程并制作操作镜头 |
| 参考片、音乐、已有素材 | 对齐节奏、气质和声音方案 |

资料不齐也可以先做脚本，并列出需要补充的具体素材。

### 3. 开始制作

```text
使用 $product-promo-film，根据我提供的产品手册和界面素材，
制作一支 60 秒中文产品宣传片，面向第一次了解产品的用户。
先给我完整分镜脚本，明确每镜画面、文案、操作、声音和时长。
脚本确认后，再制作完整视频和可编辑工程。
```

## 一张可制作的分镜表

下面是虚构软件的 **12 秒操作片段示例**，用于说明脚本粒度，不代表某个产品的真实功能，也不是已生成的样片。

| 时间 | 画面与动作 | 上屏文字 | 声音与验收 |
| :--- | :--- | :--- | :--- |
| 0–3s | 输入框进入，逐步输入已确认的指令 | 用户输入原文 | 字体清晰，留足阅读时间 |
| 3–5s | 鼠标移向按钮，停留并点击 | 按钮原有文字 | 点击声与按下动作对应 |
| 5–8s | 点击释放后显示处理中状态 | 正在生成 | 反馈必须晚于点击 |
| 8–12s | 结果展开，镜头推近重点内容并停留 | 已确认的结果说明 | 图片比例正确，结果不被提示遮挡 |

完整工作表见 [分镜脚本模板](assets/script-template.md)。

## 质量标准

### 让观众看清

- 中文字号和行距适应最终成片尺寸；同级标签保持相同字号。
- 输入框与输入文字一起调整，关键信息有明确层级和阅读时间。
- 提示不遮挡演示内容，图片保持比例，不出现意外黑边或裁切。

### 让操作成立

- 先满足操作前提，再移动鼠标、点击按钮、展示结果。
- 使用一致的鼠标样式，以指针尖端判断按钮落点。
- 状态数字、批次、步骤高亮与真实业务阶段一致。

### 让修改连续

- 保留上一版已确认的内容与工程，记录每轮修改范围。
- 用同一时间线检查关键帧、短段动效和最终编码文件。
- 同时核对声音、转场、接缝与最终视频，不仅检查静态截图。

## 工具与运行环境

制作通常采用 **Remotion + React / TypeScript**，结合浏览器采集、FFmpeg 和可用字体；已有适合的可编辑工程可以继续沿用。

仓库附带一个需要 Node.js 的时序检查器：

```bash
node scripts/check-timeline.mjs /path/to/project/qa/timeline.json
```

它检查声明时间表中的镜头覆盖、事件依赖、点击顺序和指针落点。它不会自动观看视频，不能代替视觉与声音检查。输入格式见 [时序说明](references/timeline.md)。

## 常见问题

**只有产品手册，能开始吗？**  
可以先整理产品理解、脚本和素材缺口。真实界面的还原需要截图、录屏、演示环境或其他可核验资料。

**安装 Skill 后就有视频生成模型了吗？**  
没有。Skill 组织制作流程；渲染、配音和生成式素材由运行环境中的工具完成，仓库不附带模型服务、密钥或商业素材授权。

**能像 Shotcraft 一样浏览大量动态样片吗？**  
当前版本没有镜头样片画廊或成套渲染模板。它侧重资料到脚本、真实界面演示、修改规范和成片验收；本页中的分镜是说明示例。

**一定要沿用冰川蓝吗？**  
不用。历史项目配色是参考，新产品优先采用自己的品牌字体、色彩和视觉风格。

**可以分享原始项目素材吗？**  
本仓库不包含原始对话、账号信息或产品媒体素材。公开案例应另外核对展示权限与素材授权。
