# Drama 系列的历史经验（不是新产品固定事实）

以下是这批制作对话里的定位与风格选择。新手册、新版本和当前用户指令优先。不要把示例项目、数字、平台按钮永久写死。

| 产品 | 历史叙事方向 | 合适的证明方式 |
|---|---|---|
| DramaTV | 创作空间与镜头精修；无限画布、剧本模式、画布Agent | 同一故事从创意/文本到分镜、资产、图片、视频；节点连接与结果预览 |
| DramaFlow | 一键流、低门槛、批量推进 | 剧本审查→资产提取与生成→提示词与匹配→视频生成；真实自动流程加必要人工点击 |
| DramaData | 两种创作方式的共同管理底座 | 成本管控、人员管控、项目监管、项目复盘；从创建预算到审核修改闭环 |

## 反复确认过的制作约束

- 功能讲解尽快进入产品证据，避免一直抽象品牌动画。
- 录屏/截图常被指定为结构参考而非成片贴图。遵从每段要求，不擅自把参考图直接盖上去。
- 界面重建的结构和 Agent 文本忠实于来源；用户明确否定过营销摘要卡、跨栏箭头和虚构流程。
- 上屏引导逐步收敛为小型标题/步骤条、真实鼠标点击、Data 目标边框呼吸。不是完全禁止箭头，当前明确要求优先。
- TV 的冷蓝画布标签倾向透明浅填充、冷色细边，不用金色；品牌结尾的鎏金功能卡则曾被接受，两者不能混为一套。
- Data 的原页面有浅色专业风格，后续也采用冰川蓝。必须先确定本片版本，不混用几个时期的页面样式。
- 文字稳定与清晰优先，Data 曾反复返工“上下摆动、很糊”；别把背景漂浮动画施加给整页正文。
- 输入特写放大整体框和字体；步骤提示过大则整体缩小并留出内容区域。
- 新增内容时保留原有品牌入口动效；简化颜色不等于移除动画。
- 同级框字必须同字号；先完整读得下，再做齐宽和对齐。
- 关键帧确认后生成视频；收到“生成视频”要交付实际可播放成片。

## 两个必须区分的状态例子

角色资产：`设定已完成（第7批/共7批） → 鼠标点击生成全部角色 → 正在生成x/63 → 图片逐张出现 → 生成完成`。设定63条不代表角色图片已经生成63张；最新修订不要求点击前额外添加“图片生成63/63”。

成片审核：`无封面待上传 → 上传提交 → 审片人收到 → 进入对应集数/时间码 → 通过或批注 → 制作人收到批注 → 修改重传`。只有已展示输入或前置条件才能出现对应结果。不要把“提交”“审核通过”“最终交付”合成一个瞬间。

## 复用已有工程

用户提供已有工程时，优先查找输入特写、品牌卡、画布标签、Agent侧栏和作品详情等已确认组件。本技能不包含这些产品的原始工程。

复用前核对源文件与最终成片的对应关系，清理临时路径与旧文案，以最新用户反馈为准。
